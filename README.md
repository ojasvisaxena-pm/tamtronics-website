# Tamtronics website

The Tamtronics marketing site on Next.js (App Router), Payload CMS and MongoDB. It is a migration of the static site in `../tamtronics-html`, which is left unchanged. All page content is edited in the Payload admin.

## Run it locally

Needs Node 20.9+ and MongoDB (local or Atlas).

```bash
cp .env.example .env     # set MONGODB_URI and PAYLOAD_SECRET
npm install
npm run seed             # loads the original site's content; never overwrites existing content
npm run dev
```

- Website: http://localhost:3000
- Admin: http://localhost:3000/admin. The first visit asks you to create the first admin user.

## Environment variables

| Variable | Required | Notes |
| --- | --- | --- |
| `MONGODB_URI` | Yes | Connection string, including the database name. Server-side only. |
| `PAYLOAD_SECRET` | Yes | Long random value (`openssl rand -hex 32`). Changing it logs all admins out. |
| `NEXT_PUBLIC_SERVER_URL` | Yes | Where this deployment is served, no trailing slash. Sets admin CORS/CSRF. Baked in at build time. |
| `MEDIA_DIR` | No | Folder for uploads. Defaults to `./media`. Must be persistent in production. Ignored when `S3_MEDIA_BUCKET` is set. |
| `S3_MEDIA_BUCKET`, `S3_MEDIA_REGION` | On Amplify | Store uploads in a private S3 bucket. Required on serverless hosts. Uses the default AWS credential chain. |
| `APP_SECRET_ID` | On Amplify | Secrets Manager secret read at build time by `scripts/amplify-env.mjs`. See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md#aws-amplify-staging). |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS` | No | Mail server for "Forgot password?" emails and inquiry notifications. Without `SMTP_HOST`, nothing is sent: reset links are printed in the server log, and form submissions are still saved. |
| `EMAIL_FROM_ADDRESS`, `EMAIL_FROM_NAME` | No | Sender of those emails. The address defaults to `SMTP_USER`. |
| `INQUIRY_RECEIVER_EMAIL` | No | Who gets new inquiries when the CMS lists no recipients. Comma-separated. |
| `REVALIDATE_SECRET` | No | Bearer token for `POST /api/revalidate`, which clears the page cache after changes made outside the CMS (scripts, restores). Signed-in CMS users don't need it. See [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md#caching-and-content-updates). |

Canonical URLs, social tags and the sitemap use **Public website address** in Site Settings, not an environment variable.

## How it's organised

```
src/app/(frontend)   Public pages, inquiry API, preview, health check, sitemap
src/app/(payload)    Payload admin and API (generated by Payload)
src/collections      Pages, Media, FormSubmissions, Users
src/globals          Header, Footer, Platform Layers, Site Settings, Business Inquiry Form
src/blocks           Page sections and the elements that go inside them
src/components       Rendering; interactive.tsx and InquiryForm.tsx are the client components
src/lib/email        SMTP settings, inquiry emails and their HTML templates
src/diagrams         Original SVG artwork, generated by scripts/extract-diagrams.ts
scripts/seed.ts      The original site's content as data
tests                Playwright suite, including comparison against the original site
docs                 Migration inventory, editor guide, deployment, QA report
```

After changing a collection, global or block: `npm run generate:types && npm run generate:importmap`.

`scripts/migrate-inquiry-form.ts` moved an existing database to the Business Inquiry Form setup: it copies the form wording from the contact page into the new global, and old `inquiries` into `form-submissions`. Preview by default, `--apply` to save; safe to rerun. A fresh database gets the same through `npm run seed`.

`scripts/clean-urls.ts` rewrote links saved in the CMS from `/page.html` to `/page` when the site switched to clean URLs. It's kept for databases restored from before that switch: run it without flags to preview, then with `--apply`.

## Decisions worth knowing

- **Clean URLs.** Pages live at `/platform`, `/about` and so on. The original static site's `/platform.html` addresses redirect there permanently (308), as does `/index.html`. Canonical tags and the sitemap use the clean addresses.
- **The CSS is the original `main.css`**, with three font variables pointed at `next/font`, the two architecture tab selectors, and one rule for the logo.
- **Diagrams are code, not content.** The animated SVGs are kept byte-for-byte. Editors choose a diagram and can change the captions around it, but text inside one needs a developer. The usage chart is the exception: it's drawn from data editors can change.
- **Four-layer explorer text is one global**, because Home and Platform show the same content.
- **No redirects plugin data is needed for launch**; the Redirects collection is there for future URL changes.
